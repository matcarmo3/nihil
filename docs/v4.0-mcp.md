# Nihil v4.0 — writing MCP servers (design draft)

A real MCP server (a dozen read-only tools over a set of record files, used by a Claude agent)
was written in v3.9 first, to see what the language lacks. It works with what exists:

- stdio: `<< line` reads one JSON-RPC message per line, and the output is flushed before every
  read (§8.3), so each answer leaves before the next message is awaited. `... 0;` flushes
  without reading (for notifications sent between reads). Logs go to `!>>` (standard error).
- reading JSON: `json(key)`, `json_items()`, `json_text()`; `json(key)` gives the raw text of a
  value, so a request `id` (number or string) is echoed back untouched.
- running a long job in a child process: `["env", "DATA_DIR=…", "bin/report"].start(…)`.

What hurt, in order:

1. **A runtime error ends the server.** One index out of bounds in a tool, and the agent loses
   every tool. The v3.9 code guards each access by hand (`value_at`, `arg_int`).
2. **Writing JSON is text concatenation.** Every answer, every schema: quotes, commas and
   escapes by hand (`"{\"name\": " + name.json_quote() + …`). The tool list is the most fragile
   part of the server.
3. **The schemas repeat what the methods already say.** `stock_report(store = 0,
   product = 0, month = 12, to = 12)` already has the names, the types (from the defaults) and the
   defaults; the schema writes them again, and the dispatch (`mcp_call`) a third time.

## 1. Protected calls: `?name(args)`

```text
r? = ?tool_report(store, product, month);      // STRING?: _ when a runtime error happened inside
r == _ { >> "failed: " + ?!; }                 // ?! : the text of the last caught error
```

- `?` before a call makes it return `T?`; a runtime error anywhere inside it (index out of
  bounds, division by zero, invalid input, `could not read`, …) gives `_` instead of ending the
  program, and its message goes to `?!` (a STRING, `""` when none).
- It mirrors `@` / `@?`: `@ path` ends the program when the file cannot be read, `@? path` gives
  `_`. No new word: `?` before a name never started an expression.
- Nested protections work: the innermost catches.
- `out of memory` is not caught (the heap may be inconsistent).

**Implementation.** A protection stack in the runtime (saved `rsp`, `rbp` and the resume
address, 3 words per level, 64 levels). `rt_error` and its siblings look at the stack before
writing to stderr: when a level is active they copy the message to `?!`'s buffer, restore
`rsp`/`rbp` and jump to the resume address with `_` in `rax`. The garbage collector is
conservative and scans the stack it finds, so nothing else changes. The compiler emits
`rt_protect_push` before the call and `rt_protect_pop` after it (two new jump-table entries;
`layout.inc`, `runtime.asm`, `00_data.nihil`, `47_records.nihil`, `50_expressions.nihil`).
Cost when nothing fails: two calls and three stores.

Tests: every runtime error of §8.3 inside `?f()`; nesting; a protected call in a loop of
100 000 iterations (no stack growth); the output written before the error stays written.

## 2. JSON out and in

```text
>> item.to_json();                    // {"id": 293, "store": 1, "name": "SOFT DRINKS", …}
>> items.to_json();                   // [{…}, {…}]
>> totals.to_json();                  // a MAP: {"1": 12.5, "2": 3.0}
>> [1, 2, 3].to_json();               // [1, 2, 3]
p = PRODUCT.from_json(text);          // fields by name; a missing one keeps the default
ps = PRODUCT.from_json_items(text);   // the items of a JSON array
```

- `to_json()` on every type: INT, FLOAT (the shortest text that reads back the same, as `$`),
  BOOL, STRING (as `json_quote`), an optional (`null` for `_`), arrays, maps (keys as text) and
  records (an object with the model's field names, in declaration order; STRING fields without
  the padding of their width).
- `MODEL.from_json` uses the model's field names and types; a value of the wrong type is `_`
  for an optional field and a runtime error otherwise (catchable with `?`).
- Prelude code over the model's field list, which the compiler already has (the table reader
  uses it): `__nihil_r_to_json(model, record)` and `__nihil_r_from_json`.

## 3. Tools from signatures: `tools("tool_")` and `call_tool("tool_", name, arguments)`

```text
// the stock of a product in a store for a month or a period
tool_report(store = 0, product = 0, month = 12, to = 12) { … : text; }

// the stores, optionally of one region
tool_stores(region = "") { … }

>> tools("tool_");      // [{"name": "report", "description": "the stock of a product …",
                        //   "inputSchema": {"type": "object", "properties": {"store":  {"type": "integer",
                        //   "default": 0}, …}, "required": []}}, …]
r? = ?call_tool("tool_", name, arguments);   // calls the method by name, arguments by parameter name
```

- At compile time the compiler knows every method: its name, its parameters, their types (from
  the defaults) and the comment above it. `tools(prefix)` is a constant STRING built at compile
  time from the methods whose names start with the prefix: the name without the prefix, the
  comment as the description, one property per parameter (INT → integer, FLOAT → number,
  BOOL → boolean, STRING → string, with the default). Open question: how to mark a parameter as
  required (every parameter has a default today); until it is decided, none is required and the
  defaults apply.
- `call_tool(prefix, name, arguments)` is a dispatcher the compiler generates: one branch per
  such method, reading each parameter from the JSON object `arguments` by name (missing → the
  default; a number given as text is accepted, as the v3.9 server's `arg_int` did), and giving
  the method's result as text (`to_json()` for anything that is not a STRING). An unknown name
  gives `_` (so `?call_tool` covers both a failure and an unknown tool).
- With 1–3, `lib/mcp.nihil` needs no callback from the program: `mcp_serve("prefix", name,
  version)` answers `tools/list` with `tools(prefix)` and `tools/call` with
  `?call_tool(prefix, …)`, turning `_` into `isError: true` with `?!` as the text.

The server then shrinks to its tools:

```text
@ "lib/mcp.nihil";
// the products to restock first in a store for a month
tool_restock_priority(store = 0, month = 12, top = 10) { … }
…
mcp_serve("tool_", "stock", "1.0");
```

## Later

- HTTP transport (Streamable HTTP): request headers (`Mcp-Session-Id`), streamed answers
  (Server-Sent Events) and more than one connection at a time; needs the v4.0 HTTP client's
  socket work and a way to wait on several descriptors (`poll`).
- Progress and cancellation of long calls: waiting on the standard input and a child process at
  the same time (the same `poll`).
